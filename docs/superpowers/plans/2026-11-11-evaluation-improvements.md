# 평가 개선점 반영 계획 (2026-11-11)

2026-11-11 프로젝트 평가(디자인 6.5 / 사용성 7 / 코드 7)에서 나온 개선점을 반영한다.
소유자의 조건: **지금 입력된 데이터에 영향을 주지 않는다.**

## 데이터 보호 규칙 (모든 작업에 적용)

1. 기존 문서를 고치거나 옮기는 자동 작업(마이그레이션·과거 달 채우기·정규화 쓰기)을 넣지 않는다.
2. 문서 구조와 ID 체계를 바꾸지 않는다. 새 필드는 선택 사항으로만 추가한다.
3. `firestore.rules`는 건드리지 않는다 (콘솔에 붙여 넣는 과정의 실수가 곧 잠금이다).
4. 저장 경로를 고칠 때는 "덜 쓰거나, 쓰기 전에 묻는" 방향으로만 바꾼다.
5. 검증은 `tools/mock/`(가짜 Firestore)과 Node 테스트에서만 한다. 가짜 Firestore의 쓰기 기록
   (`window.__writes`)으로 "앱을 열고 둘러보는 것만으로는 기존 문서를 건드리지 않는다"를 확인한다.

## 범위에서 뺀 것

- 과거 달 고정비 자동 채우기 (과거 달에 새 기록이 생겨 누적 잔액이 바뀐다 — 규칙 1)
- Firestore 규칙 강화, 허용 이메일 해시화 (규칙 3)
- 거래 리스너를 최근 N개월로 좁히기, import 순환 해소, 오프라인 영속 캐시 (구조 변경 — 테스트를 먼저 갖춘 뒤)
- 데스크톱 2단 재배치, 휴대폰 요약 바를 스크롤 영역으로 옮기기 (범위가 크고 취향이 갈린다)
- 작성자(누가 썼나) 선택 칸, 건너뛴 고정비 되살리기 (새 쓰기 기능)

## 단계

### 0. 검증 기반
- `tools/mock/` — 가짜 Firebase 모듈 + import map으로 앱을 그대로 띄우는 개발용 페이지, 검사 스크립트(`checks/`)
- `package.json`(`"type": "module"`), `tools/check-syntax.js`, `tests/`(Node 내장 테스트 러너, 가짜 Firestore 위에서 `db.js` 실행)

### 1. 확인된 버그
- 누적 잔액 캐시가 다른 달 값으로 굳는 문제 (`calcAccumulatedBalance`)
- 고정비를 고치면 이번 달에 손본 금액이 되돌아가는 문제 (`syncFixedItemTransactions`)
- 휴대폰 서랍의 로그아웃이 하단 탭에 가려지는 문제
- 지출 0원일 때 "변동비 0원 (100%)", 필터가 없는데 "조건에 맞는 내역이 없어요"
- 숫자 필드가 문자열일 때 속성 주입, 모듈 로드 실패 시 안내 없음, `.then`에 `catch` 없음

### 2. 데이터 안전
- 전체 백업(JSON) 내려받기
- 카테고리 일괄 변경 전 확인 ("이 내역만 / 모두 바꾸기")
- CSV 재가져오기: 이미 있는 내역은 건너뜀(선택 시 덮어쓰기), 다른 사람 파일과의 ID 충돌 방지, 금액을 못 읽은 행 집계
- 다른 달을 보는 중 추가할 때의 기본 날짜, 날짜가 들어간 저장 안내
- 느린 연결에서의 저장 안내, 입력 중 창 닫힘 확인, 메모·예산안 입력 보존

### 3. 핵심 흐름
- 달력 날짜 탭 → 그날 내역 시트
- 목록 검색: Enter 적용, 결과 건수·합계, 여러 단어는 모두 포함
- 내용 자동완성(최근 이름 → 카테고리까지), 금액 입력(프리셋·숫자 키패드·만 단위 표시)
- 고정비 문구, 토스트 줄바꿈·검증 실패 칸 표시, 안드로이드 뒤로가기

### 4. 디자인
- 터치 기기 입력칸 16px(아이폰 자동 확대 방지), 휴대폰 글자 크기 하한
- 하단 탭 5칸(달력·목록·＋·통계·결혼), 고정비 아이콘, 라이트 모드 카테고리 점 테두리
